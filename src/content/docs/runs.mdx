# Agent runs.

A **run** gives an agent a task inside one of your [workspaces](/docs/workspaces) and lets it work on its own. You write what you want done, pick the agent (Pi or Hermes, whichever is installed in that workspace) and the folder, and the run takes it from there. It keeps going if you close the page or the terminal.

While it works you follow its log live. When it ends you get its result and, if the folder is a git repository, a branch with its changes, ready for you to review.

You can start a run in three ways, and all three see the same runs:

- From the **Runs** tab of your workspace in the portal.
- From your terminal, with `nan run`.
- From your own scripts, with the API.

## Before you start

- **A workspace that is running**, with Pi or Hermes installed. You can install either one from the **Software** panel of the workspace.
- **A plan with inference.** A run uses your workspace's own inference key, and what the agent spends counts against your plan's usage like any other request. Without inference in your plan you cannot create runs: the portal shows you the upgrade options instead.

## Start a run from the portal

<Steps>

### Open the Runs tab

Go to [cloud.nan.builders/workspaces](https://cloud.nan.builders/workspaces) and open a workspace. Next to **Overview**, **Console**, **SSH keys**, **Events** and **Backups** there is a **Runs** tab with the history of your runs in that workspace, newest first.

{/* SCREENSHOT: runs tab, the run history of a workspace with the New run button */}

### Fill in the form

Press **New run** and fill in the form:

| Field | What it is |
|---|---|
| Agent | Pi or Hermes, whichever is installed in the workspace. |
| Prompt | The task, in your own words, as you would write it to the agent in a chat. Up to 32 KiB. |
| Working directory | The folder the agent works in. It defaults to `/home/nan` and must be inside it. |
| Worktree | `auto` (the default), `on` or `off`. See [Where the agent works](#where-the-agent-works). |
| Timeout | 15, 30, 60 or 120 minutes. The run is stopped when it reaches it. |

{/* SCREENSHOT: new run form, with agent, prompt, working directory, worktree and timeout */}

### Follow it live

Click a run in the list to open its page. The log fills in as the agent works: what it says, the tools it calls and what they answer. When the run ends, the page shows how it ended, the agent's summary and, if there is one, the branch with its changes.

You can close the page at any moment. The run goes on, and its page is there when you come back.

{/* SCREENSHOT: run page with the live log, the state and the Cancel button */}

### Cancel it, if you need to

**Cancel** stops the run within a few seconds. The portal asks you to confirm first.

</Steps>

## Where the agent works

What happens to your files depends on the folder you choose and on the **worktree** setting.

| The folder is... | Worktree `auto` (default) | Worktree `on` | Worktree `off` |
|---|---|---|---|
| inside a git repository | Separate worktree and branch | Separate worktree and branch | Directly in the folder |
| not a git repository | Directly in the folder | The run fails with a configuration error | Directly in the folder |

**With a worktree**, the agent does not touch your checkout. It works in a separate copy of the repository, on a new branch called `nan-run/` followed by the first 8 characters of the run id, for example `nan-run/6f1c2a9b`. When the agent ends, whatever it changed is committed on that branch. The run **never pushes**: the branch stays in the repository inside your workspace, and you decide what to do with it. If the agent changed nothing, the branch is deleted.

To review the changes and bring them in, open a terminal in your workspace ([over SSH or the Console tab](/docs/workspaces#connect)) and, from the repository:

```bash
git log -p HEAD..nan-run/6f1c2a9b
git merge nan-run/6f1c2a9b
```

**Without a worktree**, the agent works directly in the folder and there is no branch. Use it for folders that are not repositories, or when you want the changes right there.

The working directory must be inside `/home/nan`, your home in the workspace.

## Run states

| State | What it means |
|---|---|
| `queued` | Waiting for a free place. See [How many runs at once](#how-many-runs-at-once). |
| `starting` | Being set up in the workspace. |
| `running` | The agent is working. |
| `succeeded` | The agent finished its task. |
| `failed` | The agent stopped with an error, or the run could not start (for example, worktree `on` in a folder that is not a repository). |
| `cancelled` | You cancelled it. |
| `timed_out` | It reached its timeout and was stopped. |

Through the CLI and the API the timeout goes from 60 seconds to 2 hours. The portal offers 15, 30, 60 and 120 minutes.

## How many runs at once

How many runs work at the same time depends on the size of the workspace:

| Size | Runs at once |
|---|---|
| Micro (also the free Premium workspace) | 1 |
| Nano | 2 |
| Basic | 3 |
| Medium | 5 |
| Large | 8 |

On top of that, runs share your inference concurrency, so you can have at most **5 runs working at once across all your workspaces** (**8 on Premium**).

Runs beyond those limits are not refused: they wait in a queue and start in order, first in, first out. The queue holds up to **20 runs per workspace** and **50 in total**, and you can create up to **60 runs per hour**.

Each run works in its own process inside the workspace, with its own share of CPU and memory. If one gets out of hand, it is stopped alone: your SSH sessions and your always-on agents keep working.

## Inference and secrets

Runs use the inference key of the workspace, the same one its agents use when you work with them by hand. Their requests count against your plan's usage like any other.

Secrets in your workspace's environment file, such as that inference key or a Telegram bot token, are shown as `***` in run logs and results, so a log does not leak them.

## From the terminal: `nan run`

The [NaN CLI](/docs/nan-cli) starts and follows runs from your own terminal. You need version **0.1.24** or newer.

<Steps>

### Install or update the CLI

```bash
curl -fsSL https://nan.builders/install | bash
```

### Sign in

```bash
nan auth login --email you@yours
```

It emails you a sign-in link. Copy it from the email and paste it back into the command without opening it in the browser first: it works once. The [NaN CLI guide](/docs/nan-cli) has the details. The runs commands use that session, or the API key from the CLI's Setup tab when there is no session.

### Start a run

```bash
nan run "add tests for the date parser and make them pass"
```

The CLI streams the log to your terminal until the run ends.

</Steps>

A few more ways to start one:

```bash
# A specific workspace, agent and folder
nan run --ws develop --agent hermes --cwd /home/nan/projects/api "review the open TODOs"

# The prompt from a file, or from stdin
nan run -f task.md
git diff | nan run -

# Start it and get the id back without waiting
nan run --detach "upgrade the dependencies"
```

| Flag | Default | What it does |
|---|---|---|
| `--ws NAME` | your only workspace | The workspace to run in. If you have more than one and leave it out, the CLI lists them and exits with code 64. |
| `--agent pi\|hermes` | `pi` | The agent. |
| `--model M` | the agent's own | The model the agent uses. |
| `--cwd PATH` | `/home/nan` | The working directory in the workspace. |
| `--worktree` / `--no-worktree` | auto | Force a worktree on or off. See [Where the agent works](#where-the-agent-works). |
| `--timeout D` | `30m` | When to stop it, from `1m` to `2h`. |
| `--detach` | | Start the run, print its id and return. |
| `--idempotency-key K` | | If a retry sends the same key and request, you get the run already created instead of a second one. |
| `--json` | | Print events as JSON lines, then the finished run. |
| `-f FILE` | | Read the prompt from a file, or from stdin with `-`. |

While it streams, **Ctrl-C once** stops following the log: the run keeps going and the CLI tells you how to pick it up again. **Ctrl-C twice within 2 seconds** cancels it.

### Manage your runs

```bash
nan runs ls                # your runs, newest first
nan runs show <id>         # state, result and prompt
nan runs logs <id> -f      # follow the log until it ends
nan runs cancel <id>
```

`nan runs logs <id> --json` prints one JSON event per line, handy for scripts.

### Exit codes

`nan run` and `nan runs logs -f` exit with the outcome of the run, so a script can act on it without reading the text:

| Code | Meaning |
|---|---|
| 0 | succeeded |
| 1 | failed |
| 2 | timed out |
| 3 | cancelled |
| 4 | the workspace is not ready for it: agent not installed, no inference key or a bad configuration |
| 64 | usage error, including more than one workspace and no `--ws` |
| 65 | not signed in, session expired or not allowed |
| 69 | nan.builders unavailable, or the stream was lost (the run goes on, and the id is printed) |
| 75 | the run was accepted and is still going (`--detach`, or Ctrl-C once) |

Under `set -e`, allow for the 75 of `--detach`:

```bash
id=$(nan run --detach "upgrade the dependencies") || [ $? -eq 75 ]
```

## From the API

The same runs are available over HTTP, at `https://api.nan.builders/v1/runs`, for your own scripts and integrations.

### API keys and tokens

Two kinds of credentials work with the runs API. Both are in your [settings on the portal](https://cloud.nan.builders/):

| | **API Keys** | **Tokens** |
|---|---|---|
| Looks like | `sk-...` | `nan_pat_...` |
| Inference (models) | Yes | **No, never** |
| Platform API (runs, your workspaces) | Yes | Yes |
| Who can create them | Plans with inference | Any member with an active subscription |

A **token** is the one to give a script that only manages runs. It cannot call the models directly, but it can start runs that spend your plan, so keep it as private as an API key and revoke it if it leaks. Create it under **Settings → Tokens**:

- It is shown **once**, when you create it. Copy it then.
- You can have up to **10** active tokens.
- Each one expires after **30, 90 or 365 days**, or never.
- You can revoke any of them at any time.

Creating runs still needs a plan with inference, whatever credential you use.

<Callout title="An agent cannot launch runs by itself" variant="warning">
The key inside a workspace, the one its agents use for inference, cannot manage runs: the API answers it with `403`. An agent working in your workspace cannot start new runs on its own, unless you give it one of your own API keys or tokens.
</Callout>

### Create a run

```bash
export NAN_TOKEN="nan_pat_..."

curl https://api.nan.builders/v1/runs \
  -H "Authorization: Bearer $NAN_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: fix-date-parser-1" \
  -d '{
    "workspace": "develop",
    "agent": "pi",
    "prompt": "add tests for the date parser and make them pass",
    "cwd": "/home/nan/projects/api",
    "git_isolation": null,
    "timeout_seconds": 1800
  }'
```

| Field | Required | What it is |
|---|---|---|
| `workspace` | Yes | Name or id of the workspace. |
| `agent` | Yes | `pi` or `hermes`. |
| `prompt` | Yes | The task, up to 32 KiB. |
| `cwd` | No | Working directory, `/home/nan` by default. |
| `git_isolation` | No | `null` for auto (the default), `true` for worktree on, `false` for off. |
| `timeout_seconds` | No | From 60 to 7200. 1800 (30 minutes) by default. |
| `model` | No | The model for the agent. Its own by default. |

The answer is the run, with its `id` and its `state`. The `Idempotency-Key` header is optional: if a retry sends the same key with the same body, you get the run that was already created instead of a second one.

### Follow it

The events of a run come as a stream of server-sent events when you ask for `text/event-stream`. With `curl -N` you see them as they arrive:

```bash
curl -N https://api.nan.builders/v1/runs/$RUN_ID/events \
  -H "Authorization: Bearer $NAN_TOKEN" \
  -H "Accept: text/event-stream"
```

Each frame is one of these:

- `event: run_event`, with an `id:` line: one event of the log (a message, a tool call, its result...). Send the last `id` you saw as the `Last-Event-ID` header to resume after a dropped connection, without missing or repeating anything.
- `event: state`: the run changed state.
- `event: end`: the run is over and its log has been sent in full. The data is the finished run. The stream closes after it.

Every 15 seconds the stream sends a comment line to keep the connection open. A stream lasts 30 minutes at most: if it closes before the `end`, reconnect with `Last-Event-ID` and carry on. Without the `Accept` header, the same endpoint answers pages of JSON instead: pass the `next_after` of each page as `?after=` to get the next one.

To see how it ended:

```bash
curl https://api.nan.builders/v1/runs/$RUN_ID \
  -H "Authorization: Bearer $NAN_TOKEN"
```

### Cancel it

```bash
curl -X POST https://api.nan.builders/v1/runs/$RUN_ID/cancel \
  -H "Authorization: Bearer $NAN_TOKEN"
```

### List your runs

```bash
curl "https://api.nan.builders/v1/runs?workspace=develop&state=running&limit=20" \
  -H "Authorization: Bearer $NAN_TOKEN"
```

All filters are optional. If there are more runs than fit in a page, the answer has a `next_cursor`: pass it as `?cursor=` to get the next page.

### Errors

Errors use the same format as the inference API:

```json
{"error": {"message": "...", "type": "...", "param": null, "code": "tier_restricted"}}
```

| Status and code | What to do |
|---|---|
| `400 invalid_request` | A field is wrong. `param` says which one. |
| `403 tier_restricted` | Your plan does not include inference. Upgrade it to create runs. |
| `403 workspace_key_not_allowed` | You used the key from inside a workspace. Use an API key or a token. |
| `404` | The workspace or the run does not exist, or is not yours. |
| `409 idempotency_conflict` | You reused an `Idempotency-Key` with a different body. Use a new key. |
| `409 workspace_not_running` | Start the workspace first. |
| `409 agent_not_installed` | Install the agent from the **Software** panel, or pick the other one. |
| `409 no_inference_key` | The workspace has no inference key. Check that your plan includes inference. |
| `429 run_queue_full` | The queue is full (20 per workspace, 50 in total). Wait for some runs to end. |
| `429 rate_limited` | More than 60 runs in the last hour. Try again later. |

## FAQ

<Details summary="Does a run push my code anywhere?">

No. With a worktree, the changes stay on a `nan-run/...` branch in the repository inside your workspace. Pushing, merging or throwing them away is up to you.

</Details>

<Details summary="What happens if I close the browser or the terminal?">

Nothing: the run keeps going in the workspace. Open its page in the **Runs** tab, or run `nan runs logs <id> -f`, to pick it up again.

</Details>

<Details summary="Can I use runs without inference in my plan?">

No. Runs use the models through your workspace's inference key, so creating them needs a plan with inference. You can still create a token and list your workspaces and runs.

</Details>

<Details summary="Does a run touch my SSH sessions or my always-on agents?">

No. Each run has its own share of the workspace's CPU and memory. If one gets out of hand, only that run is stopped.

</Details>

<Details summary="Where do I get help?">

Write in `#support` on Discord.

</Details>
